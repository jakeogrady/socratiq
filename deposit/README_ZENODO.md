# Socratic guiding questions in synthetic arithmetic data: matched LoRA runs (revision v2)

Supporting data, adapters, predictions and code for the article *Low-Cost LoRA
Fine-Tuning of Small Language Models for Multi-Step Arithmetic Reasoning* by
Jake O'Grady, Asena Isik Gürhan, Chee Fong Ting and Effirul Ramlan
(University of Galway).

Cite this record: https://doi.org/10.5281/zenodo.23236018

We generated 20,000 GSM8K-derived arithmetic problems with step-by-step
solutions and rendered each solution twice: with a guiding question before
every reasoning step (Socratic) and without those questions (non-Socratic).
Qwen3-0.6B, Qwen3-1.7B and Llama-3.2-1B-Instruct were fine-tuned with LoRA on
both versions, and Qwen3-0.6B also on nested subsets of 5,000 and 10,000
examples. All models were evaluated on GSM8K, MultiArith, SVAMP and GSM-Hard
under a protocol fixed before any run.

## Where the article's tables come from

In `socratiq-v2-evidence.zip`, `evidence/tables/` holds the tables as typeset:
Table 1 `primary_family.tex`, Table 2 `accuracy_p0_greedy.tex`, Table 3
`format_p0_greedy.tex`, Table 4 `resources.tex`, and in the supplement
Table S1 `configurations.tex`, S3 `sensitivity.tex`, S4
`diagnostics_p0_greedy.tex`, S5 `outcomes_p0_greedy.tex`, S6
`secondary_paired.tex`, S7 `accuracy_p0_sc5.tex`, S8 `p4_summary.tex` and S9
`second_tier.tex`. The CSV files hold the same numbers at full precision.

## Verifying and rebuilding

1. Check the archives with `shasum -a 256 -c SHA256SUMS.txt`.
2. Unpack the code archive, then unpack the data and runs archives into its
   root directory, so that `data/` and `runs/revision_v2/` sit next to `src/`.
   Unpack the two adapter archives into `runs/revision_v2/training/<run>/adapter/`
   (the Llama folders are renamed in the archive; the manifests give the run IDs).
3. Run `python -m src.revision_v2.tables build`. It re-scores every response
   from its raw text, checks every count and hash against the manifests, and
   writes the evidence directory again.

Each training and evaluation manifest records the protocol hash, the commit,
the hardware, the library versions, and the SHA-256 of its outputs.

## Data format

Training files are JSON Lines with the fields `question`, `answer`,
`example_id`, `source_id` and `variant_id`. Row *i* is the same example in the
Socratic and non-Socratic file of each directory. Answers end with
`#### <number>`.

## Notes

- In 4 of the 18,000 training examples, a reasoning line ends in a question
  mark. This text is shared by both arms. One of them
  (`gsm8k-train-003040-v02`) contains a garbled reasoning step that passed the
  automatic checks.
- The run manifests and logs are unchanged from the training machines, so
  their hashes verify. They include the machines' user names, host names and
  working-directory paths.
